# 거기까지!

2026 EST AI Challengers 해커톤 프로젝트입니다. 베이커리의 과거 판매기록을 바탕으로 다음 날 예상 판매량과 생산 조정안을 보여주고, 점주가 최종 생산량을 결정하도록 돕습니다.

## 현재 대시보드

- **생산계획:** 기존 계획·예상 판매량·10개 단위 조정안 비교, 최종 수량 수정 및 브라우저 저장
- **판매기록:** 최근 기록 확인, CSV 업로드, 입력 데이터에 따른 예측값 재계산
- **제품관리:** MVP 상품인 크루아상의 생산 단위·보관 방법·판매 기한 표시
- **설정:** 매장명과 기본 생산 단위 관리, 현재 데이터·모델 적용 범위 안내

시연 데이터는 FastAPI의 최종 결합 예측 모델로 전달됩니다. 화면은 P50 예상 판매량과 P75·재고·예약·생산 단위를 반영한 추천 생산량을 표시합니다. 모델 API가 꺼져 있으면 연결 오류와 최근 평균 임시값을 표시합니다.

CSV 형식은 첫 행에 `날짜,요일,판매수량,메모`를 사용합니다.

## 사용자 흐름

1. **접속 / 시작 화면:** 페이지에 처음 들어오면 포스터 이미지가 전체 화면에 뜨고, 그동안 매장·제품·판매기록 초기 데이터를 백그라운드에서 불러옵니다. 데이터 로딩이 끝나면 포스터가 서서히 사라지며(약 1.5초 페이드아웃) 대시보드가 드러납니다. FastAPI 연결에 실패하면 포스터가 사라진 자리에 연결 오류 안내가 표시됩니다.
2. **기본 진입 - 생산계획:** 판매기록을 기반으로 내일 예상 판매량(P50/P75)과 추천 생산량이 자동 계산되어 표시됩니다. 스테퍼로 최종 생산 수량을 조정하고 저장하면 브라우저(localStorage)에 남습니다.
3. **판매기록으로 이동:** 사이드바에서 전환. 최근 판매 기록을 확인하거나 CSV를 업로드하면, 그 데이터를 바탕으로 생산계획 페이지의 예측이 다시 계산됩니다.
4. **제품관리로 이동:** MVP 상품(크루아상)의 생산 단위·보관 방법·판매 기한을 확인하고 수정합니다. 수정한 값은 예측 계산(배치 크기 등)에 반영됩니다.
5. **설정으로 이동:** 매장명, 기본 생산 단위를 관리하고 현재 데이터·모델 적용 범위를 확인합니다.
6. 네 개 메뉴는 사이드바 클릭만으로 전환되며, 페이지를 새로고침하지 않는 한 매장/제품/판매기록/예측 상태는 `App.jsx`에서 계속 유지됩니다.

### 시작 화면(포스터) 이미지 교체하는 법

`frontend/public/img/splash.png`가 기본 시작 화면 이미지입니다. 다른 이미지로 바꾸고 싶으면 같은 경로·같은 파일명(`splash.png`)으로 덮어쓰기만 하면 됩니다. 파일명을 바꾸고 싶다면 [Splash.jsx](frontend/src/layout/Splash.jsx)의 `src="/img/splash.png"` 부분도 함께 고쳐야 합니다.

## 시연 시나리오 (CSV 업로드로 변화 보여주기)

기본으로 깔려있는 목업 데이터만 보여주면 화면이 계속 똑같아서 "AI가 실제로 계산한다"는 느낌이 잘 안 삽니다. 판매기록이 갑자기 늘어난 CSV를 시연 중에 직접 업로드해서, 예상 판매량·추천 생산량이 그 자리에서 바뀌는 걸 보여주는 방식을 추천합니다.

`demo-data/판매기록_급증_시연용.csv` 파일을 미리 준비해뒀습니다. 최근 5일간 판매량이 SNS 화제로 급증해서 품절이 이어지는 상황을 가정한 데이터입니다.

**녹화 순서 예시:**

1. 서버를 켜고 화면을 연 상태에서 **생산계획** 페이지를 먼저 보여줍니다. (평소 수준의 예상 판매량·추천 생산량이 표시됨)
2. 사이드바에서 **판매기록**으로 이동합니다.
3. **CSV 파일 선택** 버튼을 눌러 `demo-data/판매기록_급증_시연용.csv`를 선택합니다. 표에 최근 며칠 판매량이 급격히 늘어난 게 바로 반영됩니다.
4. 다시 **생산계획** 페이지로 돌아가면, 방금 올린 데이터를 반영해 예상 판매량과 추천 생산량이 눈에 띄게 올라간 걸 확인할 수 있습니다. (모델이 최근 판매기록에 더 큰 가중치를 두기 때문입니다.)
5. 필요하면 스테퍼로 최종 수량을 조정하고 **계획 저장**까지 눌러 마무리합니다.
6. 원래 상태로 되돌리려면 판매기록 페이지의 **예시 데이터로 되돌리기**를 누르면 됩니다.

CSV 안의 날짜는 과거로 고정되어 있어(2026년 8~9월), 나중에 다시 시연해도 "판매기록 날짜는 예측일보다 이전이어야 합니다" 오류 없이 그대로 쓸 수 있습니다.

## 시작하기 (처음부터)

이 저장소를 처음 받는 컴퓨터 기준으로, 필요한 프로그램 설치부터 서버 실행까지 순서대로 정리했습니다. Windows 기준입니다.

### 1. 필수 프로그램 설치

아래 4가지가 필요합니다. 이미 설치되어 있다면 건너뛰어도 됩니다.

| 프로그램 | 확인 방법 | 설치 링크 |
| --- | --- | --- |
| Git | PowerShell에서 `git --version` | https://git-scm.com/download/win |
| Python 3.10 이상 | PowerShell에서 `py -3 --version` | https://www.python.org/downloads/ (설치 시 **Add python.exe to PATH** 체크) |
| Node.js 20 이상 | PowerShell에서 `node -v` | https://nodejs.org/ko (LTS 버전) |
| Visual Studio Code | 실행 아이콘 확인 | https://code.visualstudio.com/ |

설치 후에는 PowerShell(또는 VSCode 터미널)을 새로 열어야 PATH가 반영됩니다.

### 2. 저장소 내려받기 (clone)

원하는 폴더에서 PowerShell을 열고 실행합니다.

```powershell
git clone https://github.com/est-worldpeace/worldpeace.git
cd worldpeace
```

### 3. VSCode로 열기

```powershell
code .
```

(`code` 명령이 안 먹으면 VSCode를 직접 실행해서 `File > Open Folder`로 방금 받은 `worldpeace` 폴더를 엽니다.)

VSCode 상단 메뉴 `Terminal > New Terminal`로 터미널을 하나 더 열면, 아래 백엔드/프론트엔드를 각각 다른 터미널에서 동시에 실행할 수 있습니다.

### 4. 백엔드 서버 준비 (FastAPI, 최초 1회)

```powershell
cd backend
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
cd ..
```

### 5. 프론트엔드 준비 (React + Vite, 최초 1회)

```powershell
cd frontend
npm.cmd install
cd ..
```

### 6. 서버 실행

최초 준비(4, 5번)가 끝난 뒤부터는 매번 저장소 루트(`worldpeace` 폴더)에서 아래 명령 **하나만** 실행하면 백엔드·프론트엔드가 동시에 켜집니다.

```powershell
npm.cmd install
npm.cmd run dev
```

(`npm.cmd install`은 `concurrently` 패키지를 받는 과정으로, 루트 폴더에서 최초 1회만 필요합니다.)

터미널 하나에 `[backend]`, `[frontend]` 로그가 함께 찍히며, `Ctrl+C` 한 번으로 둘 다 종료됩니다.

각자 따로 켜고 싶으면 예전처럼 터미널을 두 개 열어도 됩니다.

```powershell
# 터미널 1
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

```powershell
# 터미널 2
cd frontend
npm.cmd run dev
```

### 7. 확인

- 화면: http://127.0.0.1:5173
- API 문서: http://127.0.0.1:8000/docs
- 백엔드가 꺼져 있으면 화면에 연결 오류와 임시값이 표시됩니다.

모델 출처와 검증 방법은 `backend/app/models/README.md`, LLM·RAG·LangGraph 확장안은 `AI_FEATURES.md`를 참고하세요.
