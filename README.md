# 거기까지!

2026 EST AI Challengers 해커톤 프로젝트입니다. 베이커리의 과거 판매기록을 바탕으로 다음 날 예상 판매량과 생산 조정안을 보여주고, 점주가 최종 생산량을 결정하도록 돕습니다.

## 현재 화면

- **대시보드:** 오늘의 AI 브리핑, 예상 판매량·AI 권장 생산량·예상 폐기량·예상 절감 금액 KPI, 실제 vs 예측 판매 추이 그래프, 예측에 반영된 요인(요일 효과·최근 추세·주말 여부) 안내
- **생산계획:** 기존 계획·예상 판매량·AI 권장 생산량 비교, 폐기 위험 표시, 절감 효과, 생산량 시뮬레이션, 최종 수량 수정 및 브라우저 저장
- **판매기록:** POS 판매내역(CSV/XLSX) 업로드, 상품별 자동 분류·데이터 확인 화면, 입력 데이터에 따른 예측값 재계산
- **제품관리:** MVP 상품인 크루아상의 생산 단위·보관 방법·판매 기한·개당 원가 관리
- **설정:** 매장명과 기본 생산 단위 관리, 현재 데이터·모델 적용 범위 안내

시연 데이터는 FastAPI의 최종 결합 예측 모델로 전달됩니다. 화면은 P50 예상 판매량과 P75·재고·예약·생산 단위를 반영한 추천 생산량을 표시합니다. 모델 API가 꺼져 있으면 연결 오류와 최근 평균 임시값을 표시합니다.

**판매기록 업로드:** 판매기록 화면에서 POS에서 내보낸 CSV/XLSX 파일을 업로드하면 컬럼을 자동으로 인식합니다(`판매일자,상품명,카테고리,판매수량,단가,실판매금액` 등). 컬럼명이 애매하면 화면에서 직접 매핑을 확인한 뒤 진행하고, 여러 상품이 섞여 있어도 상품별로 자동 분류합니다 — 다만 예측 모델은 아직 크루아상만 지원하므로 다른 상품은 "모델 준비 중"으로 표시되고 가짜 예측값을 만들지 않습니다. 옛날 형식(`날짜,요일,판매수량,메모`, 상품명 컬럼 없음)도 그대로 올리면 자동으로 크루아상 데이터로 처리됩니다.

## 사용자 흐름

1. **접속 / 시작 화면:** 페이지에 처음 들어오면 포스터 이미지가 전체 화면에 뜨고, 그동안 매장·제품·판매기록 초기 데이터를 백그라운드에서 불러옵니다. 데이터 로딩이 끝나면 포스터가 서서히 사라지며(약 1.5초 페이드아웃) 대시보드가 드러납니다. FastAPI 연결에 실패하면 포스터가 사라진 자리에 연결 오류 안내가 표시됩니다.
2. **기본 진입 - 대시보드:** 오늘 확인해야 할 정보(추천 생산량, 폐기 위험, 절감 효과, 판매 추이)를 한눈에 보여줍니다.
3. **생산계획으로 이동:** 판매기록을 기반으로 내일 예상 판매량(P50/P75)과 AI 권장 생산량이 자동 계산되어 표시됩니다. 슬라이더로 여러 생산량을 미리 비교해보고, 스테퍼로 최종 수량을 조정·저장하면 브라우저(localStorage)에 남습니다.
4. **판매기록으로 이동:** 사이드바에서 전환. POS 판매내역(CSV/XLSX)을 업로드하면 데이터 확인 화면에서 기간·상품별 현황을 보여주고, "AI 생산량 예측하기"를 누르면 크루아상 데이터가 반영되어 대시보드·생산계획의 예측이 다시 계산되고 생산계획 화면으로 이동합니다.
5. **제품관리로 이동:** MVP 상품(크루아상)의 생산 단위·보관 방법·판매 기한·개당 원가를 확인하고 수정합니다. 수정한 값은 예측 계산과 절감 금액 계산에 반영됩니다.
6. **설정으로 이동:** 매장명, 기본 생산 단위를 관리하고 현재 데이터·모델 적용 범위를 확인합니다.
7. 다섯 개 메뉴는 사이드바 클릭만으로 전환되며, 페이지를 새로고침하지 않는 한 매장/제품/판매기록/예측 상태는 `App.jsx`에서 계속 유지됩니다.

### 시작 화면(포스터) 이미지 교체하는 법

`frontend/public/img/splash.png`가 기본 시작 화면 이미지입니다. 다른 이미지로 바꾸고 싶으면 같은 경로·같은 파일명(`splash.png`)으로 덮어쓰기만 하면 됩니다. 파일명을 바꾸고 싶다면 [Splash.jsx](frontend/src/layout/Splash.jsx)의 `src="/img/splash.png"` 부분도 함께 고쳐야 합니다.

## 시연 시나리오

### 1) POS 업로드 → 여러 상품 자동 분류 → AI 예측 (기본 데모)

판매기록 화면의 **예시 데이터로 둘러보기** 버튼을 누르면 `frontend/public/demo/pos-sample.csv`(크루아상·소금빵·식빵 3개 상품, 30일치)를 자동으로 불러와 업로드와 동일한 흐름을 그대로 보여줍니다. 같은 파일을 **예시 POS 파일 다운로드**로 받아서 직접 업로드해봐도 됩니다.

1. **판매기록**으로 이동해 **예시 데이터로 둘러보기**(또는 파일 업로드)를 클릭합니다.
2. 컬럼이 표준 이름과 일치해 매핑 확인 없이 바로 **데이터 확인 화면**이 뜹니다 — 기간, 판매일수, 인식된 상품 수(3개), 총 판매수량과 함께 상품별로 "크루아상: 예측 가능 / 소금빵·식빵: 모델 준비 중"이 표시됩니다.
3. **AI 생산량 예측하기**를 누르면 크루아상 데이터만 예측에 반영되고 자동으로 **생산계획** 화면으로 이동합니다.
4. 대시보드·생산계획에서 새 예측값, 폐기 위험, 절감 효과가 갱신된 걸 보여줍니다.

### 2) 판매량 급증 시나리오 (극적인 변화 보여주기)

`demo-data/판매기록_급증_시연용.csv`(옛 4컬럼 형식, 상품명 컬럼 없음 — 업로드하면 자동으로 크루아상 데이터로 처리됩니다)를 이용해 최근 5일 SNS 화제로 판매량이 급증하는 상황을 보여줄 수 있습니다.

1. **생산계획** 페이지에서 평소 수준의 예상 판매량을 먼저 보여줍니다.
2. **판매기록** → **POS 판매파일 선택**으로 `demo-data/판매기록_급증_시연용.csv` 업로드 → 데이터 확인 화면에서 **AI 생산량 예측하기** 클릭.
3. 생산계획·대시보드로 이동해 예상 판매량·AI 권장 생산량이 눈에 띄게 오른 걸 확인합니다.
4. 원래 상태로 되돌리려면 **예시 데이터로 둘러보기**를 다시 누르면 됩니다. (새로고침하면 온보딩 화면부터 다시 시작합니다 — 아래 "완전한 온보딩" 참고)

### 3) 판매량 급감 시나리오 (폐기 위험 · 절감 효과 보여주기)

`demo-data/판매기록_급감_시연용.csv`로 최근 5일 장마·한산으로 판매량이 뚝 떨어지는 상황을 보여줄 수 있습니다. 기존 계획(100개)은 그대로인데 예상 판매량만 크게 떨어지므로, **폐기 위험 배지가 "높음"으로 바뀌고 절감 효과 숫자가 커지는 걸** 극적으로 보여주기 좋습니다. 사용법은 급증 시나리오와 동일하게 업로드 → 데이터 확인 화면 → AI 생산량 예측하기.

세 파일 모두 날짜가 과거(2026년 8~9월)로 고정되어 있어, 나중에 다시 시연해도 "판매기록 날짜는 예측일보다 이전이어야 합니다" 오류 없이 그대로 쓸 수 있습니다.

## 완전한 온보딩

앱을 처음 열거나 새로고침하면 더 이상 가짜 목업 데이터가 자동으로 뜨지 않습니다. 대신 전체화면 온보딩이 먼저 뜨고, "POS 판매파일 업로드" 또는 "예시 데이터로 둘러보기" 중 하나를 선택해야 대시보드로 넘어갑니다. 이 상태는 세션(브라우저 상태) 기준이라 새로고침할 때마다 다시 나타납니다.

## 시작하기 (처음부터)

이 저장소를 처음 받는 컴퓨터 기준으로, 필요한 프로그램 설치부터 서버 실행까지 순서대로 정리했습니다. Windows 기준입니다.

### 1. 필수 프로그램 설치

아래 4가지가 필요합니다. 이미 설치되어 있다면 건너뛰어도 됩니다.

| 프로그램 | 확인 방법 | 설치 링크 |
| --- | --- | --- |
| Git | PowerShell에서 `git --version` | https://git-scm.com/download/win |
| Python 3.10 이상 | PowerShell에서 `py -3 --version` | https://www.python.org/downloads/ (설치 시 **Add python.exe to PATH** 체크) |
| Node.js 20 이상 | PowerShell에서 `node -v` | https://nodejs.org/ko (LTS 버전) |
| Visual Studio Code | 실행 아이콘 확인 | https://code.visualstudio.com/ |

설치 후에는 PowerShell(또는 VSCode 터미널)을 새로 열어야 PATH가 반영됩니다.

### 2. 저장소 내려받기 (clone)

원하는 폴더에서 PowerShell을 열고 실행합니다.

```powershell
git clone https://github.com/est-worldpeace/worldpeace.git
cd worldpeace
```

### 3. VSCode로 열기

```powershell
code .
```

(`code` 명령이 안 먹으면 VSCode를 직접 실행해서 `File > Open Folder`로 방금 받은 `worldpeace` 폴더를 엽니다.)

VSCode 상단 메뉴 `Terminal > New Terminal`로 터미널을 하나 더 열면, 아래 백엔드/프론트엔드를 각각 다른 터미널에서 동시에 실행할 수 있습니다.

### 4. 백엔드 서버 준비 (FastAPI, 최초 1회)

```powershell
cd backend
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
cd ..
```

### 5. 프론트엔드 준비 (React + Vite, 최초 1회)

```powershell
cd frontend
npm.cmd install
cd ..
```

### 6. 서버 실행

최초 준비(4, 5번)가 끝난 뒤부터는 매번 저장소 루트(`worldpeace` 폴더)에서 아래 명령 **하나만** 실행하면 백엔드·프론트엔드가 동시에 켜집니다.

```powershell
npm.cmd install
npm.cmd run dev
```

(`npm.cmd install`은 `concurrently` 패키지를 받는 과정으로, 루트 폴더에서 최초 1회만 필요합니다.)

터미널 하나에 `[backend]`, `[frontend]` 로그가 함께 찍히며, `Ctrl+C` 한 번으로 둘 다 종료됩니다.

각자 따로 켜고 싶으면 예전처럼 터미널을 두 개 열어도 됩니다.

```powershell
# 터미널 1
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

```powershell
# 터미널 2
cd frontend
npm.cmd run dev
```

### 7. 확인

- 화면: http://127.0.0.1:5173
- API 문서: http://127.0.0.1:8000/docs
- 백엔드가 꺼져 있으면 화면에 연결 오류와 임시값이 표시됩니다.

모델 출처와 검증 방법은 `backend/app/models/README.md`, LLM·RAG·LangGraph 확장안은 `AI_FEATURES.md`를 참고하세요.
